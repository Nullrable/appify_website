处理实时拍摄的同一 OCR 和翻译流水线也处理从设备相册导入的照片。可用于截图、已保存的街牌或菜单照片，以及朋友分享的图片。

## 导入如何工作

1. **从相册选择。** 点击相机页面的相册图标会通过 `image_picker` 打开系统照片选择器。选中的图像被复制到应用的临时目录；原图保留在原位置。
2. **读取物理方向。** 相册照片有可靠的 EXIF 方向标签，因此导入路径直接使用 EXIF 而无需触碰加速度计。图像在 OCR 之前旋转到正确的正向。
3. **同一 OCR 流水线。** 图像被送入相机路径使用的同一分叉 `vision_text_recognition` 引擎。"导入"与"拍摄"无需特殊处理——结果页和翻译行为完全相同。
4. **保存到历史。** 与相机拍摄一样，导入的照片可以保存到本地翻译历史。保存的副本是压缩的缩略图，而非完整的相册照片，以保持存储在合理范围内。

## 何时使用导入而非拍摄

- **截图。** 翻译作为截图保存的 UI 字符串、错误对话框或网页片段。
- **已拍摄的照片。** 翻译旅行、会议或朋友聊天中的照片，无需重新拍摄。
- **草图或白板。** 白板笔记和草图的照片通常比重新拍摄更清晰，尤其是当表面有反光时。
- **文档。** 由其他应用捕获的收据、名片和标签的快照可以无需切换即可翻译。

## 隐私

导入的照片经过与实时照片相同的本地流水线。它们在内存中处理，永远不会上传到我们运营的任何服务器。保存的历史副本仅存储在设备上的应用本地数据库中，可以从历史页面单独删除。

## 限制

- **现有旋转会被保留。** 由操作系统旋转的照片会在 OCR 之前重新旋转回正向。这是导入时"OCR 返回乱码文本"问题的最常见原因。
- **大尺寸原件会缩小。** 高于 OCR 引擎推荐分辨率的照片会在识别前缩小。设备上的原始照片不受影响。
- **无批量导入。** 每张照片都需要单独的一次点击。如果你需要翻译许多保存的照片，请逐张进行；单张图像的 OCR + 翻译通常在几秒内完成。
